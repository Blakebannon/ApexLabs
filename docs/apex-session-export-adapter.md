# Apex customer session-bundle adapter

## Supported contract

Apex Labs 0.3 supports exactly `apex-session-export/1.0.0`, the existing
customer-facing Session Analysis Bundle. Newer or older schemas are refused.
This compatibility does not imply compatibility with a future high-resolution
Research export.

Use the bundle in its approved external storage location; do not copy it into
this repository:

```powershell
apex-labs apex-session inspect "D:\external-data\session.zip"
apex-labs apex-session validate "D:\external-data\session.zip" --collection-record "D:\external-data\collection-record.json"
apex-labs apex-session ingest "D:\external-data\session.zip" --collection-record "D:\external-data\collection-record.json" --output "D:\external-data\normalized-session"
```

Real ingestion requires a matching `apex-labs.collection-record/v1` sidecar and
a clean Apex Labs commit. `--integration-validation` exists only for a reviewed
adapter test while code is dirty; its output is permanently marked
`integration_validation_only` and scientifically ineligible.

## Source semantics

`telemetry.csv` is not timestamped raw simulator telemetry. Each row is a
one-metre distance bin. `sample_count` reports how many source frames were
represented. Brake is the bin maximum. Throttle, steering radians, and speed in
metres per second are bin arithmetic means. Radians and metres per second are
authoritative; degrees and km/h are display conveniences checked at their
declared precision. Brake/throttle use a 0-to-1 ratio, speed is non-negative,
distance is metres from lap start, and positive steering is left. The customer
bundle does not establish axes or signs for channels it does not contain.

The adapter therefore emits `distance_bin` records, not `telemetry_sample`
records. Available aggregate channels use `derived` provenance with the source
method and source-frame count. An empty channel in an unsampled bin becomes an
explicit `unavailable` value; it never becomes measured zero and is never
interpolated. Time-domain concepts remain unavailable.

The normalized stream retains the bundle hash, source manifest hash, every
payload hash, product/schema version, adapter and normalization version, code
and schema identity, exact sidecar hash, source row, aggregation method, and
deterministic normalized content hash. Absolute local paths are not included in
the normalized artifact or fingerprint.

The source reports a floating track length while exporting integer one-metre
bins. In the reviewed contract, `lap_fraction` behaves as `distance_m /
total_bins` rounded to six decimals, rather than using the floating track length
directly. Apex Labs preserves and validates the exported fraction; it does not
replace it. Until the product contract specifies the denominator normatively,
the distinction remains an adapter-conformance ambiguity.

## Product-derived classifications

Lap validity, exclusions, reference selection, incidents, finding regions,
deterministic explanations, and AI explanations are generated by Apex Sim
Coach. They are useful traceable source annotations, not independent evidence
that the detector is correct.

`product-annotations.json` is integrity-bound to the normalized manifest and
hard-codes all of the following to false: scientific evidence, training label,
ground truth, product recommendation, and scientific promotion. These values
are not copied into Apex Labs finding records. Any later analysis must evaluate
the underlying telemetry independently; using the product detector output as
both target and proof would be circular validation.

## Validation and safety

The reader snapshots and hashes the external ZIP before parsing. It rejects
duplicate/case-ambiguous names, traversal, absolute/drive/UNC/device paths,
backslashes, directories, symlinks, encryption, unexpected entries, missing or
unmanifested files, duplicate manifest entries, size/hash mismatches,
unsupported versions, malformed UTF-8/JSON/CSV, duplicate JSON keys or CSV
headers, row-width errors, non-finite numbers, excessive counts/sizes, and high
compression ratios. Parsing is bounded and telemetry is streamed.

Cross-file validation covers lap/bin uniqueness and ordering, validity,
reference/exclusion coherence, primary versus composite exclusion reasons,
sample/coverage totals, missing-channel behavior, unit conveniences, finding
keys/ranks/ranges, reviewed/best/comparable laps, and repeated session/product
identity. Scientifically meaningful defects are refused or retained as quality
information; they are not silently repaired.

Passing validation establishes structural integrity and supported source
semantics only. It does not establish consent, authorship, detector correctness,
scientific validity, or production approval.
